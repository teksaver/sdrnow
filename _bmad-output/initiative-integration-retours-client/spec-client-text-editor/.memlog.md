- (capability) CAP-1: L'administrateur peut sélectionner n'importe quelle unité de sens sur staging pour éditer côte à côte FR et EN avec preview CSS temps réel en pleine largeur et bascule automatique de la langue affichée.
- (capability) CAP-2: L'administrateur peut appliquer uniquement une emphase d'accroche (<em>), une importance forte (<strong>) ou un saut de ligne (<br>) sur les blocs riches (collage nettoyé en texte brut), tandis que les blocs plain restent verrouillés en texte pur.
- (capability) CAP-3: L'administrateur peut enregistrer ses modifications sur Staging (< 10 ms + commit [skip ci] sur branche staging) et générer un lien Read-Only (?preview=<token>) permettant à un tiers de consulter FR/EN en 1 clic sans ouvrir le staging au public.
- (capability) CAP-4: L'administrateur peut publier les textes validés directement en Production (< 10 ms sur /var/www/html + commit [skip ci] sur branche main) avec validation serveur (interdiction des blocs vides et purge HTML).
- (capability) CAP-5: L'administrateur peut réinitialiser le Staging depuis la Production pour restaurer sur staging.sdrnow.fr (et la branche staging) les textes actuellement en ligne sur sdrnow.fr sans toucher à la Prod.
- (constraint) 1 unité de sens = 1 bloc FR/EN unique (fusion de hero.title_pre et hero.title_highlight en hero.title) pour préserver la liberté syntaxique FR/EN.
- (constraint) Zéro classe CSS ni <span> dans le JSON de traduction : seules les balises HTML5 sémantiques <em>, <strong> et <br> sont autorisées dans les blocs rich.
- (constraint) Staging jamais accessible au grand public (401/403 par défaut) ; écriture réservée au compte admin, lecture externe uniquement via jeton ?preview=<token>.
- (constraint) Aucun token GitHub côté client ; synchronisation Git effectuée par le micro-service VPS avec [skip ci] pour éviter toute race condition avec deploy.yml.
- (decision) Extraction des prescriptions d'implémentation (attributs data-i18n, routes API, patch HTML <10ms, styles Tailwind de <em>/<strong>) dans le companion conventions.md conformément à Spec Law règle 2.
- (assumption) Les pages de mentions légales (/mentions-legales et /en/legal-notice) suivent le même schéma d'édition data-i18n que la page d'accueil.
- (assumption) Les secrets du micro-service (identifiants admin, secret preview, Fine-Grained PAT GitHub) sont provisionnés sur le VPS via le pipeline OpenTofu/GitHub Actions existant.
- (question) Le jeton Read-Only (?preview=<token>) est-il statique (révocable manuellement) ou à expiration automatique (ex. 7 jours) ?
- (question) L'authentification admin repose-t-elle sur le Basic Auth HTTP de Caddy ou sur un login par formulaire/cookie HttpOnly géré par le micro-service ?
