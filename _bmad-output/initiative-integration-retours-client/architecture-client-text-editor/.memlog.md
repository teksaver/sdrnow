- (constraint) Inherited AD-2 (architecture-sdrnow-infra): Caddy est le serveur web frontal unique (HTTPS auto, file_server, basicauth, reverse_proxy).
- (constraint) Inherited AD-3 (architecture-sdrnow-infra): Reproductibilité Git/OpenTofu obligatoire — toute mutation de texte sur le VPS doit être commitée sur GitHub pour survivre à une recréation d'instance.
- (constraint) Input SPEC-client-text-editor (CAP-1..CAP-5 + conventions.md): Éditeur In-Page data-i18n (plain vs rich), duo sémantique HTML5 <em>/<strong>/<br>, patch HTML <10ms + commit GitHub [skip ci], Basic Auth admin + jeton ?preview=<token> invalidé à chaque révision.
- (direction) Mode choisi : Coaching path ; livrable unique : architecture spine (build-substrate).
- (decision) AD-4 (Paradigm: Static Prod / Gatekept Staging Proxy): sdrnow.fr reste servi en statique pur par Caddy (file_server sur /var/www/html) ; staging.sdrnow.fr passe en reverse_proxy 127.0.0.1:3001 vers le micro-service Node qui gère le contrôle d'accès (?preview=<token> vs Basic Auth admin) et injecte <script src='/__editor.js'> à la volée uniquement pour admin.
- (decision) AD-5 (Zero-Dependency Node Runtime & Semantic Leaf DOM): Le micro-service VPS utilise uniquement les APIs natives de Node 20 (node:http, node:fs, node:crypto, fetch) sans node_modules sur le serveur ; tout élément [data-i18n] dans Astro est une feuille sémantique ne contenant jamais d'autre [data-i18n] ni de balise hors <em>, <strong>, <br>.
- (version) Node.js 20 LTS (natif sur VPS Debian/Ubuntu via cloud-init, aligné avec .github/workflows/deploy.yml).
- (decision) AD-6 (Local-First Atomic Mutation & 202 Accepted Git Sync Queue): Les routes POST /api/{staging,publish,reset} valident le payload, patchent atomiquement (.tmp + renameSync) le disque local en <10ms, répondent HTTP 202 Accepted (indiquant que le patch local est actif et que le commit GitHub [skip ci] est en file d'attente), et séquentialisent les commits GitHub via un mutex en mémoire avec 1 retry sur 409.
- (decision) AD-7 (Dual-Gate Access Control & Revision-Bound HMAC Preview Token): staging.sdrnow.fr bloque par défaut (401/403). Deux portes exclusives : Basic Auth admin (active l'injection de /__editor.js et autorise POST /api/*) ou jeton ?preview=<hmac> calculé via HMAC-SHA256(STAGING_PREVIEW_SECRET, sha256(staging/translations.json)) qui dépose un cookie HttpOnly lecture seule et s'invalide automatiquement dès que staging/translations.json change.
- (decision) AD-8 (Strict Semantic Sanitization & Key Whitelist): Le dictionnaire src/i18n/translations.json fait foi sur la liste des clés et leur type (plain vs rich). Toute écriture (client paste et serveur POST /api/*) rejette les clés inconnues ou vides, supprime toute balise sur les clés plain, et n'autorise que <em>, <strong> et <br> sans attributs sur les clés rich.
- (decision) Reviewer Gate Fixes: (1) Monotonic revision counter in /var/www/staging/.revision included in HMAC preview token so /api/reset and A->B->A edits always invalidate prior links; ?preview= query param evaluated before cookie, Path=/; Secure; HttpOnly, and invalid ?preview= returns 403 without WWW-Authenticate popup. (2) Timing-safe Basic Auth hashes both inputs with SHA-256 (32 bytes) before timingSafeEqual; service runs as User=caddy Group=caddy on Ubuntu 22.04 LTS (ubuntu_jammy) provisioned idempotently via deploy.yml + cloud-init.yaml. (3) Build copies src/i18n/translations.json to dist/translations.json; all [data-i18n] nodes (including optional pricing.strategy_unit) rendered unconditionally; /api/publish syncs both main and staging branches sequentially.
