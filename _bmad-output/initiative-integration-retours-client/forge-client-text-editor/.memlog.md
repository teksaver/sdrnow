goal: Mettre à l'épreuve le besoin d'édition autonome par le client et trancher l'architecture d'édition/style
status: complete
updated: 2026-10-19T11:27
---

- (assumption) Le client (Jean-Charles) a besoin d'un outil d'édition directe FR/EN avec preview CSS pour modifier les textes de la landing page.
- (decision) Rejet d'un outil limité au staging avec moulinette manuelle : si le client édite lui-même, la publication en prod doit pouvoir suivre sans blocage humain.
- (lock) Architecture retenue : Éditeur In-Page léger sur-mesure (via attributs data-i18n sur la vraie page Astro) offrant preview CSS native en direct, édition FR/EN côte à côte et publication automatisée en prod (rejet des CMS tiers TinaCMS/Keystatic/Decap).
- (lock) Granularité et style : 1 unité de sens (titre, paragraphe, puce) = 1 bloc FR/EN unique. Édition via mini-WYSIWYG sémantique bridé (Gras / Emphase couleur / Saut de ligne) sans exposer de syntaxe Markdown ni autoriser de HTML arbitraire ('gribouillis').
- (crack) Risque de 'gribouillis' et d'incohérence visuelle si le client choisit lui-même entre Gras et Orange (ex: texte orange sur fond orange dans Pricing.astro, ou gras invisible dans un H1 déjà extrabold) ou s'il copie-colle depuis Word dans un contenteditable.
- (lock) Contrat HTML5 sémantique pour le style inline : duo <em> (emphase d'accroche stylée en orange text-primary not-italic) et <strong> (importance stylée en gras font-bold) + <br>. Aucune classe CSS ni <span> dans les fichiers de traduction.
- (crack) Conflit de source de vérité et sécurité : deploy.yml fait un 'rm -rf' du serveur à chaque push Git (risque d'écraser les textes édités s'ils ne sont pas commités dans Git), et impossible d'exposer un token GitHub côté navigateur.
- (lock) Pipeline de publication : Micro-service sur le VPS Scaleway (protégé derrière Caddy Basic Auth sur staging.sdrnow.fr) qui valide/nettoie le JSON (whitelist de clés + uniquement <em>, <strong>, <br>), applique la mise à jour localement sur le serveur en < 1s (staging + prod), et pousse en tâche de fond un commit de src/i18n/translations.json sur GitHub.
- (crack) Race condition CI/CD : si le commit GitHub de tâche de fond déclenche deploy.yml, et que le client clique 2 fois sur Publier en 1 minute, le build CI du 1er clic écrasera le serveur 2 minutes plus tard.
- (lock) UX & Workflow à 2 paliers : Tiroir bas d'écran FR/EN côte à côte avec bascule auto de la langue prévisualisée, et choix entre 'Enregistrer sur Staging' (patch /var/www/staging + commit [skip ci] sur branche staging pour partager le lien pour avis) et 'Publier en Prod' (patch /var/www/html + commit [skip ci] sur branche main).
- (lock) Garde-fou d'édition : Bouton 'Réinitialiser le Staging depuis la Prod' permettant d'écraser les essais du Staging avec les textes actuellement en ligne sur la Prod (sans jamais toucher à la Prod) et interdiction de publier un bloc vide.
- (lock) Contrôle d'accès Staging : Staging jamais accessible au grand public (401/403 par défaut). Authentification compte 'admin' (Jean-Charles) requise pour afficher l'éditeur et appeler les API d'écriture ; génération d'un lien secret de partage Read-Only (?preview=<token> posant un cookie de session lecture seule pour naviguer entre FR et EN) pour obtenir un avis externe en 1 clic.
