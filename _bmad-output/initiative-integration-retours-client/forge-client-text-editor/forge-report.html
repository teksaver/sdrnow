BMad Forge Idea • Initiative : integration-retours-client

Éditeur Client Bilingue In-Page (SDRnow)

Permettre à Jean-Charles d'éditer en autonomie les textes FR/EN avec vraie preview CSS Tailwind, balisage HTML5 sémantique strict (<em> / <strong>), partage Read-Only sur Staging et publication instantanée en Prod.

🔒 Décisions Verrouillées (Locks)

1. Éditeur In-Page sur staging.sdrnow.fr

Annotation des composants Astro avec data-i18n. Le client clique sur un texte directement sur la vraie page et voit le rendu Tailwind en temps réel (pleine largeur conservée).

2. 1 Unité de sens = 1 Bloc FR/EN

Chaque titre, paragraphe, puce, chiffre KPI ou CTA est un bloc unique (fusion de hero.title_pre + hero.title_highlight en hero.title) pour préserver l'ordre grammatical propre à chaque langue.

3. Duo HTML5 Sémantique (<em> & <strong>)

Zéro classe CSS ni <span> dans le JSON. Dans les blocs rich, deux boutons : <em> (emphase d'accroche en orange text-primary not-italic) et <strong> (importance en gras) + <br>. Blocs plain (KPIs, prix, CTA) en texte brut strict.

4. Tiroir Bas d'Écran FR/EN & Auto-Switch

Au clic, un tiroir flottant en bas d'écran affiche 🇫🇷 FR et 🇬🇧 EN côte à côte. Le focus dans FR ou EN bascule instantanément la langue de toute la page sous les yeux du client.

5. Workflow 2 Paliers + Reset depuis la Prod

Trois actions : Enregistrer sur Staging (patch HTML <10ms + commit [skip ci] sur staging), Publier en Prod (patch HTML <10ms + commit [skip ci] sur main), et Réinitialiser le Staging depuis la Prod.

6. Compte Admin + Lien Read-Only (?preview=token)

Staging fermé au public (401/403). Seul le compte admin (Jean-Charles) peut éditer/publier. Il peut copier un lien secret ?preview=<token> donnant un accès 100 % lecture seule en 1 clic à ses relecteurs.

⚡ Failles Débusquées & Neutralisées (Cracks Survived)

Le « gribouillis » HTML du copier-coller

Un champ contenteditable natif injecte des <span style="..."> lors d'un copier-coller depuis Word/Docs. Parade : interception de paste en text/plain et purge serveur stricte.

Conflit de Source de Vérité avec deploy.yml

deploy.yml exécute rm -rf sur le serveur à chaque push Git. Parade : le micro-service VPS patche le HTML statique localement ET synchronise src/i18n/translations.json sur GitHub.

Race Condition CI/CD au double-clic « Publier »

Si le commit GitHub déclenchait deploy.yml, deux publications rapprochées s'écraseraient mutuellement 2 minutes plus tard. Parade : commit automatique tagué [skip ci] puisque le HTML est déjà patché en 5 ms.

Fuite de privilèges lors d'une demande d'avis

Partager le même Basic Auth client donnait les droits de mise en prod aux relecteurs. Parade : séparation stricte entre session admin (écriture) et jeton ?preview= (lecture seule).

🚫 Options Rejetées (Rejected)

Moulinette manuelle par le développeur

Trop frustrant pour le client s'il a déjà fait le travail d'édition et de calage visuel sur Staging.

CMS Tiers (Keystatic, Decap, TinaCMS)

Pas de vraie preview CSS sans dupliquer les composants Astro (Keystatic/Decap), ou pas d'édition FR/EN côte à côte et dépendance SaaS externe (TinaCMS).

1 style = 1 bloc de traduction séparé

Rend la traduction FR/EN impossible quand l'ordre des mots change et empêche le client de déplacer l'accent tonique dans sa phrase.

Syntaxe Markdown visible dans des Textareas

Charge cognitive inutile pour un profil commercial B2B et perte de fidélité visuelle.
